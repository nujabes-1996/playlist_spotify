## Story

As a user,
I want a navigable app shell with the three main pages,
so that the dashboard structure is in place and ready to receive features.

## Acceptance Criteria

1. **Given** the frontend is running, **When** I open http://localhost:5173, **Then** the `AppShell` renders with a `NavBar` containing links to Dashboard (`/`), Config (`/config`), and Logs (`/logs`).
2. **Given** I am on any route, **When** I click a NavBar link, **Then** the corresponding page renders without a full page reload (React Router v7 SPA navigation).
3. **Given** the three routes, **When** each page renders, **Then** it displays a meaningful placeholder — page title visible, no blank pages, no console errors.
4. **Given** the app entry point, **When** `main.tsx` loads, **Then** a `QueryClient` is initialized and available via `QueryClientProvider` wrapping the entire app.
5. **Given** shadcn/ui is configured, **When** I inspect the project, **Then** `components.json` exists and at least one shadcn/ui component is installed (e.g., `Button`).
6. **Given** the Vite proxy configuration, **When** the frontend makes a request to `/api/v1/*`, **Then** it is forwarded to `http://backend:8000/api/v1/*`.

### React Router v7 — Key API Notes

**Use `createBrowserRouter` + `RouterProvider`** (recommended v7 approach for SPA):

```typescript
// frontend/src/App.tsx
import { createBrowserRouter, RouterProvider, Outlet } from 'react-router-dom'
import AppShell from './components/layout/AppShell'
import DashboardPage from './pages/DashboardPage'
import ConfigPage from './pages/ConfigPage'
import LogsPage from './pages/LogsPage'

const router = createBrowserRouter([
  {
    path: '/',
    element: <AppShell />,
    children: [
      { index: true, element: <DashboardPage /> },
      { path: 'config', element: <ConfigPage /> },
      { path: 'logs', element: <LogsPage /> },
    ],
  },
])

export default function App() {
  return <RouterProvider router={router} />
}
```

**v7 breaking change awareness:**
- `useNavigate`, `useLocation`, `NavLink`, `Link` — same API as v6 ✅
- `<Outlet />` — same API as v6 ✅
- Data router (`createBrowserRouter`) is now the default/recommended — use it

### `NavBar.tsx` Structure

```tsx
// frontend/src/components/layout/NavBar.tsx
import { NavLink } from 'react-router-dom'

export default function NavBar() {
  return (
    <nav className="border-b px-6 py-4 flex gap-6">
      <NavLink to="/" end>Dashboard</NavLink>
      <NavLink to="/config">Config</NavLink>
      <NavLink to="/logs">Logs</NavLink>
    </nav>
  )
}
```

**Important:** Use `<NavLink>` (not `<Link>`) — NavLink applies `aria-current="page"` on the active route automatically. Use the `end` prop on the Dashboard link so it only activates on exactly `/`, not on child routes.

### TanStack Query v5 Setup

**v5 API differences from v4:**
- `QueryClient` constructor: same
- `QueryClientProvider`: same
- `useQuery` options: `onSuccess/onError/onSettled` callbacks **removed** (don't use them — they'll cause TS errors)
- `cacheTime` → **renamed to `gcTime`** (don't use `cacheTime`)
- `isLoading` vs `isPending`: `isPending` is the new primary loading state for `useQuery`

```typescript
// frontend/src/main.tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import './index.css'
import App from './App.tsx'

const queryClient = new QueryClient()

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
    </QueryClientProvider>
  </StrictMode>,
)
```

**Provider nesting:** `QueryClientProvider` wraps `App` (which renders `RouterProvider`). This ensures TanStack Query is available in all route components.

### Architecture Constraints — MUST FOLLOW

- **Routing:** React Router v7 — `createBrowserRouter` + `RouterProvider`. Do NOT use `<BrowserRouter>` wrapper style (legacy v5 pattern).
- **Component naming:** PascalCase files — `AppShell.tsx`, `NavBar.tsx`, `DashboardPage.tsx`.
- **Hooks naming:** camelCase prefixed `use` — reserved for TanStack Query hooks in `hooks/` (not needed in this story).
- **Tailwind v4:** No `tailwind.config.ts` file. CSS-first configuration only.
- **shadcn/ui:** Components go in `src/components/ui/` (auto-managed by shadcn CLI).
- **Shared layout:** `src/components/layout/` for `AppShell` and `NavBar`.
- **Pages:** `src/pages/` is acceptable for this story's placeholder pages. Future stories will add feature-specific components in `src/features/`.

### Anti-Patterns to Avoid

- ❌ `tailwind.config.ts` — this is Tailwind v3 style; don't create it
- ❌ PostCSS config (`postcss.config.js`) for Tailwind — v4 uses the Vite plugin
- ❌ `@tailwind base; @tailwind components; @tailwind utilities;` in CSS — this is v3 syntax; use `@import "tailwindcss";` in v4
- ❌ `<BrowserRouter>` wrapper in `main.tsx` — use `createBrowserRouter` in `App.tsx` instead
- ❌ `onSuccess`/`onError` on `useQuery` — removed in TanStack Query v5
- ❌ `cacheTime` in QueryClient config — renamed to `gcTime` in v5
- ❌ Removing the Vite proxy — it's already correct, leave it as-is
- ❌ Creating new `src/assets/` files — remove the default Vite logo/hero imports from App.tsx
